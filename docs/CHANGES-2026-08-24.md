# Collabathon 

**Build:** 24 August 2026
**Applies to:** the channel-partner mobile app and the admin panel

---

## In short

This build adds **WhatsApp OTP sign-in**, **automatic GST verification** during channel-partner
registration, and a new **Draft Registrations** page in the admin panel that shows who has
started signing up but not finished. It also fixes several issues in the app — including the
**map that would not open**, a developer list that could show out-of-date information, and
the return of the counts on the channel-partner home screen.

**WhatsApp sign-in is built but not yet testable** — the API key and message template are
still awaiting approval. GST verification needs its credentials entered. See
[Before it works](#before-it-works) at the end.

---

## 1. Sign in with WhatsApp

Channel partners will be able to receive their one-time code over **WhatsApp** instead of
email. **The work is complete and in this build, but it cannot be tested yet** — the
WhatsApp API key and message template are still awaiting approval. As soon as that
approval comes through we will enter the key and test the flow end to end. No further
development is needed; only the approval.

- Delivered through **MSG91**, using a WhatsApp authentication template (pending approval).
- Configured entirely from **Settings → Channel Partners** in the admin panel — no developer
  involvement to change a key, a template or the sending number.
- **Sandbox and production are kept separate.** You enter a test key first, confirm a real code
  arrives on a real phone, and only then switch to production. The system will not let you
  switch to an environment whose key has not been entered.
- Which method channel partners see — email code or WhatsApp code — is an admin setting. Both
  remain available.

**In the meantime, sign-in still works.** Until the WhatsApp key is entered, codes are
recorded by the system rather than sent over WhatsApp, so the flow can still be walked
through for testing. This is expected behaviour, not an error.

## 2. GST verification during registration

When a channel partner types a GST number on the registration form, it is now checked
automatically against the government GST database (via Surepass) as soon as they move to the
next field.

- Confirms the GST number is real and currently registered.
- Returns the **registered legal name**, along with registration date, status, taxpayer type and
  address on file.
- The registered name is stored **alongside** the company name the partner typed, so a reviewer
  can compare the two rather than taking the typed one on trust.

**GST remains optional.** An empty or incomplete GST field does nothing and never blocks a
registration from being submitted. This is deliberate — the check is there to inform your review,
not to stop applications. (This differs from PAN, where a rejected number does block submission.)

## 3. Draft Registrations — new admin page

**Admin panel → Channel Partner Approvals → Draft Registrations**

Previously, a channel partner who signed up and then abandoned the form partway through was
invisible in the admin panel. Nothing showed they had ever started.

The new page lists exactly those people:

| Column | What it shows |
|---|---|
| Channel Partner | Name |
| Contact | Email and mobile |
| **Progress** | How far through the form they actually got |
| Last active | When they last touched it |
| Started | When they signed up |

Three figures sit at the top: **In progress**, **Started today**, and **Stalled 7 days or more**.

These are sorted by most recently active first, because the purpose of the page is "who is
mid-way through right now and might be worth a follow-up call" — not a queue to work through.

**Nothing on this page is waiting on a decision from you.** Draft registrations are deliberately
kept out of the approval queue so that half-finished forms never sit alongside completed ones
that genuinely need approving.

## 4. Start Over during registration

A channel partner returning to a half-finished registration can now discard it and begin again,
rather than being stuck with whatever was saved previously. A confirmation is shown first.

## 5. App fixes and improvements

**The map picker now responds to every tap.**
Tapping directly on a named place — a shop, a building, a landmark labelled on Google's map —
previously did nothing at all. Only taps on blank space registered, which made the map feel
frozen. All taps now work.

**The developer list refreshes when you return to it.**
Previously the list loaded once and kept showing that snapshot. If a developer's logo, name or
project count changed in the admin panel, the app could keep displaying the old version until
fully restarted. It now refreshes each time the tab is opened.

**Project name shown on the listing card.**
The name now appears on the card image, so a listing is identifiable without opening it.

**Developer profile layout tidied.**
The verification badge and the year were previously split across two separate places, both saying
something about the same developer. They are now presented together in one place.

## 6. Since that build

Three further changes made after the build above. They are in the app now.

**The map now opens at all.** Separate from the tap fix above: the screen opened but the
map itself never appeared — a blank panel where the map should be. The Google
Maps key had been saved correctly in the admin panel, but on Android the map is drawn by
Google's own component, which reads its key from inside the installed app rather than from
the server — so a key saved in the panel could never reach it. The key is now built into the
app itself and the map loads.

> Worth knowing: changing that key in the admin panel will always need a new app build to
> take effect. It cannot be picked up while the app is running.

**Counts are back on the channel-partner home screen.** *Interested Projects* and *Approved
Interests* sit below the header again, each one tapping through to the tab that lists it.
They also refresh when you return to the screen — previously an interest accepted while the
app sat in the background left the old numbers showing until it was restarted.

**Version number moved to Profile.** It used to float in the corner of the channel-partner
home screen, overlapping the developer cards, and appeared on only one of the two
interfaces. It now sits at the foot of the Profile screen on both — under Delete Account for
channel partners, under Log Out for developers — which is where someone looks for it when
reporting a problem.

## Before it works

Two features are not active yet. Both are completed work; neither needs a new app build.

### WhatsApp OTP — waiting on approval

1. **The API key and message template are still pending approval.** This is the only thing
   holding it up, and it is outside our control — WhatsApp requires OTPs to go through an
   approved *authentication* template, which is a WhatsApp Business rule rather than an
   MSG91 one. We will test the flow end to end as soon as approval lands.
2. In **Settings → Channel Partners**, enter: the sandbox auth key, your integrated WhatsApp
   number, and the template name and language.
3. Send yourself a test code and confirm it arrives.
4. Only then switch the environment to **production** and enter the production key.

### GST verification

Requires the Surepass credentials to be configured. If they are not, the GST field simply behaves
as it did before — typed in, not checked — and registration is unaffected.
